# 一隅 · 第一轮产品与交互设计

“一隅”为本轮原型暂用名，尚未作为正式品牌确定。

## 范围与基线

2026-09-12：目录初始只有 Git 元数据，无现有应用可覆盖。本轮交付可交互设计原型，验证基础首页、收藏空间、外观设置和收藏时登录的连续体验。未接入真实认证、云端数据库，不作为正式产品上线。

## 视觉方向

暖白底色、墨色文字、苔绿强调色。留白和字号建立层级，工作区采用低对比容器。趣味集中在固定位置的火车入口，悬停、键盘聚焦、点击都能展开。报纸主题改变字形、栏目线与入口物象，保持相同导航含义。移动端将场景列表调整为横向按钮。

## 信息架构

用户 → 空间 → 场景 → 分组 → 收藏。首页搜索区区分网页与本人收藏；空间页内搜索限制为当前场景。空间切换后默认进入该空间第一个场景。收藏搜索可检索全空间并显示所属路径。

## 已实现原型路径

1. 首页 → 底部小火车展开 → 工作/生活/灵感空间 → 场景 → 分组 → 打开网址。
2. 收藏网址 → 填网址、名称、目录 → 保存 → 体验登录 → 自动保存先前填写内容。
3. 全局外观 → 主题、首页样式、明暗、配色、字体、宽度 → 即时预览。
4. 场景外观 → 按字段覆盖全局设置 → 恢复跟随全局。
5. 分组 → 卡片/列表切换，内容和顺序保持。

## 交互规则

所有外链在新标签打开。搜索框支持 / 快捷聚焦。弹窗使用原生 dialog，支持焦点约束和 Esc 关闭。网址仅允许 http/https。未登录新增时保留草稿。登录明确标注本机体验身份，避免误认为真实账号。页面遵循系统减少动态效果偏好。

原型可以自由试用外观和展示设置，并保存在本机。这不是正式版的账号设置存储策略。原型删除为确认后移除，正式版应加入回收站与撤销；原型未实现空间、场景与分组的创建、编辑、拖拽及批量操作。

## 正式架构建议

先采用单应用模块化结构：账号、收藏、搜索、主题解析、首页模板、分组展示和资源获取。不要先拆微服务。

关系型模型：users；spaces(user_id, position)；scenes(space_id, position)；groups(scene_id, position)；bookmarks(group_id, url, title, description, position)；tags 与 bookmark_tags。外观使用 user_preferences、scene_overrides 和 group_display_preferences。每个实体使用稳定 ID、创建与更新时间；可删除内容使用 deleted_at 支持回收站。

后端逐层验证资源所有权，不能信任客户端传入的用户 ID。跨设备保存需要服务端持久化，并显式处理保存中、失败重试和更新冲突。收藏标题与备注始终转义，服务端抓取网站元数据时校验 URL、重定向和内网地址，避免任意网络请求。

主题解析：系统默认 → 全局设置 → 当前场景逐字段覆盖。分组展示单独解析。首页模板与主题分离。未来主题通过能力声明列出可用配色、布局和展示样式。

## 后续设计顺序

先确认本轮视觉与四层导航，再完善新增/编辑空间、场景与分组、移动收藏、待整理和回收站。其后接入真实认证与云端持久化，再专项设计数字雨、电影、音乐主题。当前时钟是布局原型，显示实时小时与分钟，真实翻页运动尚未细化。

## 原型运行

使用 Node.js 执行 `node preview.cjs`，打开 http://127.0.0.1:4318 。数据保存在当前浏览器的 yiyu-prototype-v1 键。原型无外部前端依赖，不自动发布。
