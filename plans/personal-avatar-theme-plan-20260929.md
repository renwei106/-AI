# 个性主题：照片生成互动 3D 角色规划

调研日期：2026-09-29。状态：产品与技术规划，未实现、未调用付费生成 API、未发布。

小红书分享链接跳转登录页，尚未观看原视频。以下按用户描述的鼠标跟随、拖动转身、近远景与固定动作规划，不认定原作者采用了某种技术。后续录屏可用于核对动作幅度、镜头与构图。

**建议采用：轻量真 3D + 固定动作库 + 照片生成外观。** 首先制作 1–2 套可直接使用的精修默认角色；照片生成作为同一套主题的个性化入口。用户只需要选图、选风格、选服饰、确认效果，不接触建模、骨骼或提示词。

## 1. 本次边界与项目衔接

- 只新增本文档，保留当前工作区已有修改；不修改应用代码和线上内容。
- 实施时只增加一个用户主动选择的个性主题及其必要配置。现有主题、导航、搜索、登录、空间入口与数据行为保持一致。
- 已核实 `dist/earth-theme.js` 使用 Three.js；可沿用项目已有 3D 技术栈，但不为新主题重写地球主题。
- 已核实 `dist/desktop-pet.js` 是独立桌面陪伴模块。新主题角色独立实现，不直接替换桌宠。是否在新主题中自动隐藏桌宠会改变已有体验，应另行明确后再做。
- 主题强调色接入 `resolveThemeColor()` 与 `--accent`；随明暗主题调整环境光与背景。角色服装不自动染成主题色。
- 未来发布前核对共享服务、配置、接口、回调与环境差异，说明具体影响并取得用户明确文字确认。

## 2. 视觉方向：一个有角色陪伴的个人空间

第一版共用一个舞台和操作结构，提供两套初始角色组合：

| 初始组合 | 角色与材质 | 场景 | 动作气质 |
| --- | --- | --- | --- |
| 日常人像 | 半写实卡通人物，简洁服饰，柔和哑光 | 中性背景、轻微地面投影 | 放松站姿、轻微呼吸、转头、短挥手 |
| 宠物伙伴 | 精修猫或狗，简化毛发，保留花纹 | 相同光照体系、较低机位 | 抬头、看向鼠标、轻微尾部动作 |

此处的风格和动作是拟制作目标，不是 API 自动交付承诺。默认资产需要统一美术与人工验收。

日常主题中，保留既有搜索和导航的位置与功能，角色使用空白区域，不遮挡可点击内容。进入专门的角色预览时，角色可以放大，形成沉浸式舞台。

画面使用留白、柔和侧光、接触阴影和细腻材质建立高级感。控制环境光与服装对比，避免黑衣在暗色背景消失。第一版不加入持续粒子、镜头自动绕场、复杂房间、长时间表演或自动声音。

主题内常驻操作只保留：视图切换、互动开关、角色设置。更多选项在设置中展开。人物头部不要与搜索框或文字重叠，触屏下缩小角色占比。

## 3. 用户使用路径

### 直接使用

现有主题入口 → 个性主题 → 预览默认人物 / 默认宠物 → 应用。

默认角色无需上传照片和等待生成。预览中即可试用跟随、拖动与视图切换。

### 创建自己的角色

个性主题 → 自定义角色 → 上传照片 → 选择风格与服饰 → 查看造型预览 → 确认生成 3D → 试转动与动作 → 应用到当前配置范围。

创建面板采用大预览区域与简短设置区域：桌面宽屏约 2:1，窄屏先预览后设置。设置依次展示“照片、风格、服饰”，不一次铺开专业参数。底部提供返回与当前步骤主操作。

| 步骤 | 用户看到的内容 | 产品处理 |
| --- | --- | --- |
| 上传 | 一张人物或动物照片，主体框选 | 单主体校验，多主体时让用户选一个；提示模糊或遮挡 |
| 选造型 | 风格卡、服饰参考图 | 人物与动物展示不同的服饰选项 |
| 造型预览 | 平面参考图，可返回调整 | 明示为造型预览；用户确认后才开始较贵的 3D 生成 |
| 生成中 | 排队、制作形象、适配动作、准备预览 | 可离开并返回任务；没有真实进度时不显示假百分比 |
| 3D 预览 | 转身检查、近远景切换、试播动作 | 提供重新生成与保留当前版本；完成前不覆盖已用角色 |
| 应用 | 应用到当前主题配置范围 | 沿用现有全局 / 空间配置语义，不默认覆盖其他空间 |

显示本次消耗与剩余额度，避免切一次服装就悄悄触发生成。技术失败与“成功但不喜欢”分开处理：前者恢复产品侧额度或提供重试；后者明确重新生成的消耗规则。供应商已成功阶段可能仍产生费用，需要计入成本。

## 4. 鼠标、触屏和动作规则

| 用户行为 / 状态 | 建议表现 | 边界 |
| --- | --- | --- |
| 鼠标移动 | 头部缓慢朝向鼠标，身体仅轻微响应 | 建议先试水平 ±20°、垂直 ±10°，按角色调校；不追到背后 |
| 在角色上左右拖动 | 人物绕竖直轴转身 | 日常先限制到约 ±60°；专门预览允许 360°，背面需通过验收 |
| 松开拖动 | 缓慢停稳；日常稍后回正 | 拖动期间暂停注视，避免“身体转走、头还拧回来” |
| 点击角色 | 播放一次点头或挥手 | 设置冷却，不重复叠加；拖动结束不误触点击 |
| 进入主题 | 一次短问候，再回待机 | 不每次搜索、打开面板都重新表演 |
| 停留空闲 | 呼吸、重心微移，低频小动作 | 默认安静，不来回走动，不持续抢注意力 |
| 输入搜索 / 打开设置 | 降低动作强度或暂停响应 | 不改变输入框、键盘和导航交互 |
| 离开标签页 / 角色不可见 | 停止渲染循环 | 返回时平滑恢复 |
| 减少动态效果 | 静态或非常轻的呼吸 | 提供可见开关并尊重系统偏好 |
| 触屏 | 角色区域横向拖动、点击 | 保留页面纵向滚动，不要求陀螺仪或摄像头权限 |

“跟随鼠标”使用浏览器指针坐标，不需要摄像头，也不需要实时调用 AI。

动作优先级：直接拖动 > 点击动作 > 鼠标注视 > 待机。状态过渡做淡入淡出。注视使用头颈局部空间计算，并与身体动画分层；当人物背对用户时降低或关闭注视。

人物首批动作目标：待机、轻微呼吸、左右看、点头、挥手。动物首批目标：待机、抬头、左右看；摇尾等只对骨骼已验证的类型开启。眨眼需要眼睑骨骼或表情形变数据，普通自动绑骨不能保证，应作为条件能力。

## 5. 近景、远景与生成的关系

| 视图 | 构图 | 使用场景 |
| --- | --- | --- |
| 近景 | 头肩 / 上半身 | 更清楚地观察外观与鼠标跟随 |
| 远景 | 全身和少量地面 | 看服饰、站姿与固定动作 |

两个视图共用同一个模型，调整相机位置、目标点和构图，不生成两套人物。切换建议 400–700ms 平滑过渡，减少动态模式直接切换。不同角色按头部位置、整体高度和包围盒适配，避免耳朵、帽子或脚被裁掉。

近景质量比远景更挑剔：原图相似度、眼睛和头发边缘、脖子变形必须在近景单独验收。

## 6. 轻量个性化的边界

首期建议 2 种风格：柔和卡通、哑光潮玩。人物服饰先做 3–4 类：日常休闲、简洁通勤、运动、保留原图风格。提供同构图、同光照的参考效果，避免用户把服装展示图理解成完全精准复刻承诺。

动物先开放猫和狗；支持“原始毛色花纹、简约项圈、围巾”等选择。复杂衣物、翅膀、长裙、披风、透明材质与大量悬挂配饰后置，它们会增加结构、绑定与穿模问题。

仅有头像时，身体、服饰和背面由所选模板或生成模型补全，不宣称照片级复原。保留发型、脸型、眼镜或动物花纹等可见特征，但相似度需要用户预览确认。

首期“选服饰”在生成前完成；生成后改服饰视为制作新版本。实时换装需要标准身体、可拆分服饰和一致蒙皮，是独立的更复杂能力。动作、镜头、背景与互动强度可直接调整，无须重新生成。

人形与四足动物分别维护动作库。即便都是人形，也要映射骨骼名称、骨轴、初始姿态与比例，不能将任意模型直接接上同一动画。单个角色记录其支持能力；缺少眼部或尾部控制时只展示能可靠运行的效果。

## 7. 技术路线选择

| 路线 | 可实现效果 | 局限与适用性 |
| --- | --- | --- |
| 分层图片 / 2.5D | 轻微摆头、视差、固定姿势 | 成本较低，但不能可靠连续转身看到真实侧背面；可作为降级版本 |
| 多角度序列帧 / 视频 | 固定动作、有限角度切换 | 角度与动作组合增加素材量，任意拖动及叠加注视较难；不选为核心 |
| 轻量真 3D | 连续转动、镜头切换、骨骼动作、注视 | 最贴合需求；需要处理模型、骨骼和动作兼容性，建议采用 |

只让整张图片轻微晃动，不一定需要建模；要自然转头、转身、多视角及动作组合，建议使用真实 3D。AI 可以生成模型初稿，从而减少逐个手工建模；“生成成功”并不等于“可稳定动画”。

建议流程：

上传照片 → 主体检查 → 生成标准造型参考图 → 用户确认 → 图生 3D → 必要的减面与清理 → 绑骨 → 固定动作适配 → 近远景与动作检查 → 压缩 GLB → 保存角色资产 → 浏览器播放。

减面优先放在绑骨前；绑骨后避免不保留蒙皮信息的网格修改。风格化图片尽量生成中性背景、四肢分离、符合绑骨接口要求的姿势。

浏览器使用项目已有 Three.js 技术栈，GLTFLoader 加载模型，AnimationMixer 播放固定动作，再叠加限幅的头颈注视。[Three.js 加载文档](https://threejs.org/docs/pages/GLTFLoader.html)、[动画文档](https://threejs.org/docs/pages/AnimationMixer.html)。

## 8. API 选型与国内接入

建议优先以腾讯云 TokenHub 为国内验证入口，对比 Tripo 与混元；最终按照片集实测选主供应商，不只比较官网示例。

| 能力 | 首选候选 | 已核实能力与限制 |
| --- | --- | --- |
| 照片改造型、服饰参考 | 火山引擎 Seedream | 官方 API 支持图生图与多参考图；只承担造型图，不直接输出可动画 3D |
| 图生 3D、绑骨与固定动画 | TokenHub 的 Tripo 系列 | 有生成、绑骨检查、绑骨、动画重定向接口，适合固定动作流程 |
| 国内 3D 备选 | TokenHub 混元系列 | 有图生 3D、人物 / 动物绑骨与文生动作能力；动作输入和输出兼容性需验证 |
| 真人头像 + 模板 | 混元旧产品的 ProfileTo3D 接口 | 文档列出头像和服饰 / 人物模板；新账号可用入口、输出骨骼和可编辑性未实测，不能直接承诺使用 |
| 海外备选 | Meshy API | 有图生 3D 与绑骨；其公开 Rigging API 仍明确限制标准双足人形，不能据产品宣传推断 API 支持四足 |

官方依据：[Seedream 图片 API](https://docs.volcengine.com/docs/ark/image-generation-api?lang=en)、[TokenHub 模型列表](https://cloud.tencent.com/document/product/1823/130051)、[Tripo 动画接入](https://cloud.tencent.com/document/product/1823/137071)、[混元头像模板](https://cloud.tencent.com/document/api/1804/127685)、[Meshy Rigging API](https://docs.meshy.ai/en/api/rigging)。

Tripo 的 TokenHub 动作说明区分绑定版本：v2.5 四足预设目前列出的为行走；旧双足版本具有较多问候等动作。不能把不同版本的动作名称混用，也不能据“支持四足”承诺摇尾、坐下、撒娇全套可用。猫狗的轻微头部和尾部动作可能需自制固定片段或程序驱动，按实际骨骼验证。

Tripo 官方 SDK 还区分国内 `openapi.tripo3d.com/v3` 与海外 `.ai` 入口，可作为直连接入候选。[官方 SDK](https://github.com/VAST-AI-Research/tripo-js-sdk/blob/main/README.zh-CN.md)。TokenHub 与直连的账号、功能版本、费用不应混用。

腾讯官方已提示旧混元平台迁移到 TokenHub，新开服务优先核对 TokenHub 开通情况。[迁移说明](https://cloud.tencent.com/document/product/1804/123461)。

国内接入设计为：用户浏览器 → 自有后端 → 国内供应商入口；模型处理完转存自有对象存储，通过国内资源分发加载。密钥只在后端。供应商返回的临时 URL 不当作长期角色地址。

国外 API 不等于必然不可调用，但大陆服务器能否稳定访问、下载回传是否顺畅及账号可用区域需从实际部署环境测试。本方案不依赖用户浏览器访问国外接口。国内入口也不自动证明全部处理与存储都在境内，数据地域应以供应商服务说明确认。

## 9. 费用与成本控制

以下是 2026-09-29 查到的 TokenHub 官方公开价格计算，属于单次成功调用费用；未进行付费实测。最终以所选参数、账号控制台和账单为准。[官方价格](https://cloud.tencent.com/document/product/1823/130055)。

| 路线 | 生成 | 绑骨 | 动作 | 阶段费用示例 |
| --- | --- | --- | --- | --- |
| Tripo | 15–60 积分 × 0.07 元 = 1.05–4.20 元 | 25 × 0.07 = 1.75 元 | 10 × 0.07 = 0.70 元 / 调用 | 生成 + 绑骨 + 一次动作调用约 3.50–6.65 元 |
| 混元 | 15–60 积分 × 0.12 元 = 1.80–7.20 元 | 10 × 0.12 = 1.20 元 | 文生动作 10 × 0.12 = 1.20 元 / 调用 | 生成 + 绑骨约 3.00–8.40 元；若另调用一次文生动作再加 1.20 元 |

两条路线的“动作”能力不同，费用不能理解为同一质量、同一交付范围。多动作计费方式按实际接口返回与账单核对，不能默认一次调用无限动作。

完整角色成本还包括造型预览、成功但效果不满意的重做、减面 / 重拓扑、格式处理、人工修正、存储与流量。比如混元重拓扑公开为 50 积分，即单次 6 元，可能高于基础生成本身；这说明不能用“生成一次几元”代替完整交付报价。

统计口径采用：总生成及处理费用 / 通过角色验收的数量，再加人工和分发成本。使用一组固定样本测出可用率后，再决定用户额度或定价。

降低成本的关键：先确认便宜的造型图；固定动作只制作和校验一次，再按兼容骨架适配；避免每次互动调用模型；同一生成任务断点续作；用户点击多次不创建重复订单；模型产物长期缓存复用。

## 10. 后台与性能设计

生成是后台任务，支持排队、超时、失败恢复、余额上限、幂等与任务归属校验。状态可采用：照片检查 → 待确认造型 → 排队 → 生成模型 → 绑定与适配 → 验收 → 可预览 / 失败。前端退出不终止任务，不给出未经实测的完成时间承诺。

角色清单保存资产版本、模型地址、海报图、骨骼类型、支持动作、头部控制点、镜头预设及能力标记。界面展示可读选项，专业字段仅用于内部。

上传前说明照片用于角色生成及实际调用服务，默认不公开原图；提供删除原图和角色入口。生成文件需检查格式、体积和外部资源引用，再放行到预览。

建议先以这些数值作为优化目标，而非已达成指标：单角色压缩资源 3–8MB，移动端更低；约 2–5 万三角面为起点；1K–2K 贴图；桌面优先接近 60fps，移动端稳定 30fps。实际按目标设备和近景品质调整。

先显示海报和可用搜索，再异步加载角色；只在当前主题启用时加载对应资源；离开主题释放监听、纹理与渲染器。首期采用低成本柔光和地面阴影，避免多重实时阴影。WebGL 不可用或设备性能不足时显示静态角色，并可切回默认角色；基础搜索和导航始终可用。

## 11. 推进顺序与验收

1. **效果验证**：制作 1 个精修人物和 1 个精修宠物，完成同一舞台的近远景、拖动、注视和少量动作。本阶段不需要开放用户上传，先确定想要的质感与性能。
2. **生成验证**：用有使用授权的 12–20 张人物、猫狗照片跑 Tripo / 混元对比；记录近景相似度、背面、绑骨成功率、动作破面、耗时及每个合格角色总成本。
3. **小范围上传试用**：开放 2 种风格、有限服饰与人形 / 猫狗类别，接入造型确认、后台任务、资产预览和额度。不能稳定适配的类别暂不进入正式生成入口。
4. **扩大能力**：有数据后增加风格、服饰、动物类别与动作；实时换装、复杂表情和更多物种另立迭代。

验收必须包括：同一主题在明暗模式、桌面与手机下不遮挡搜索；连续拖动和点击不误触；头颈不反转；切镜头不裁切；固定动作前后姿态平滑；多人照片可选主体；失败任务不覆盖旧角色；刷新可找回任务；关闭主题释放资源；低性能设备降级；其他主题与原桌宠行为无无关变化。
