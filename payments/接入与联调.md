# 拾隅微信／支付宝支付接入

本次接入：微信 Native 扫码支付、支付宝电脑网站支付，一次性月度／年度会员购买。
短信、邮箱、微信登录、自动续费签约不在本次实现中。已经开通支付产品，还需要完成商户 API 身份配置。

## 当前状态与边界

- 已接入真实接口调用代码：微信 APIv3 下单／查询、支付宝电脑网站收银台／查询。
- 支付结果在后端验签，核对商户、应用、订单、金额后，才原子更新订单、会员时长账本；重复通知不会重复赠送时长。
- 套餐价格和天数读取当前后台 `/api/shiyu/plans`，不会采用浏览器传入的金额或用户 ID。
- 现有后台登录仍是演示验证码，不能作为真实收款账号身份。本机联调用独立的短期支付会话，账本归属 `payment-integration`，不会更改后台现有用户、邀请奖励和演示数据。
- 正式账号支付需设置 `identityUrl`：该后端须校验真实会话，返回 `{ "authenticated": true, "user": { "id": "...", "memberExpiresAt": 0 } }`；未登录返回 401。接口收到的 Cookie 仅传给这个受信任服务。不要配置成现有 Mock 登录接口。
- 会员账本存于支付 SQLite 数据库。当前管理后台的 Mock 用户数据尚未读取这个账本，不能把本机联调会员当成正式账号已开通。
- 连续包月／包年仍展示在原位置，但禁止付款；不会把普通一次性支付冒充自动扣款。
- 当前配置缺少商户密钥、微信 AppID 和公网 HTTPS 回调域名，真实商户接口与真实到账测试尚未完成。

## 2. 微信商户平台

使用商户超级管理员登录 [微信商户平台](https://pay.weixin.qq.com/)。

### AppID

进入 **产品中心 → AppID账号管理**，找到已关联成功的 AppID（`wx` 开头），填到 `wechat.appId`。
这是微信的 AppID，与支付宝 AppID 无关。没有关联时先完成符合微信支付要求的应用关联。

### APIv3 密钥

进入 **账户中心 → API安全 → 解密回调／APIv3密钥**。

- 尚未设置：按页面要求设置 32 字节密钥，同一个值填入 `wechat.apiV3Key`。
- 已设置：使用原来保存在本机的值。控制台一般不能再次显示，不要直接重置正在使用的密钥。

[官方设置指引](https://pay.wechatpay.cn/doc/v3/merchant/4012072195)

### 商户 API 证书及私钥

进入 **账户中心 → API安全 → 商户API证书 → 申请证书**，按官方证书工具指引下载。
把 `apiclient_key.pem` 和 `apiclient_cert.pem` 放到 `.local/payments/keys/wechat/`。
配置已对应这两个文件名；程序会从证书读取序列号，也可以填写 `wechat.serialNo`。
证书本身不等于私钥，两个文件都需保留。

[官方申请指引](https://pay.wechatpay.cn/doc/v3/merchant/4012072428)

### 微信支付公钥

同一“API安全”页，进入 **微信支付公钥 → 申请公钥／管理公钥**。
下载公钥，保存为 `.local/payments/keys/wechat/wechatpay-public.pem`；把 `PUB_KEY_ID_...` 填入 `wechat.publicKeyId`。
按控制台指引确认公钥模式已启用。若已有线上业务使用平台证书，先保留已有证书，通过 `platformCertificatePath` 加载兼容，不要直接切断旧配置。

[官方公钥指引](https://pay.wechatpay.cn/doc/v3/merchant/4013038816)

**截图里的“Native支付回调链接”不代替 APIv3 的通知地址。** 本实现下单时传入 `notify_url`，由代码配置。电脑扫码支付不依赖 JSAPI 支付授权目录，不需要为这次电脑扫码接入填写该目录。

## 3. 支付宝开放平台

打开 **控制台 → 网页／移动应用 → 拾隅 → 开发设置 → 接口加签方式**。
确认应用对应电脑网站支付能力，使用 RSA2。

### 如果还没有配置过应用密钥

在“导航站”目录运行：

```powershell
node payments/manage.cjs alipay-key
```

工具在本机生成 RSA 2048 位密钥，已存在时拒绝覆盖：

- `keys/alipay/app-private.pem`：应用私钥，只在服务器保存。
- `keys/alipay/app-public-upload.txt`：把其内容复制到支付宝“应用公钥”输入框。
- `keys/alipay/app-public.pem`：应用公钥备份。

若支付宝页面选择的是 **公钥模式**：上传上述应用公钥，保存后获取支付宝公钥；保存为 `.local/payments/keys/alipay/alipay-public.pem`。注意它与刚生成的“应用公钥”不是同一把公钥。

若已有密钥配置：先找到原私钥文件再填路径，不要生成新密钥覆盖正在使用的应用。

### 如果已选证书模式

保留已选模式，配置 `appCertPath`（应用公钥证书）、`alipayPublicCertPath`（支付宝公钥证书）、`alipayRootCertPath`（支付宝根证书），同时保留配套的应用私钥。无需改成公钥模式。

### 商户 PID

在支付宝商家平台账户信息／开放平台账户信息里查找收款商户 PID（通常 `2088` 开头、16 位），填入 `alipay.sellerId`。用于核对异步通知里的实际收款方。

[支付宝官方 SDK 配置说明](https://github.com/alipay/alipay-sdk-nodejs-all)

## 4. 域名、回调和本机联调

`publicBaseUrl` 必须填写真实可访问的 HTTPS 根地址，例如已部署后的 `https://app.shiyubox.com`，不能只填一个尚未连通的域名。以下两个地址必须由微信／支付宝服务器直接访问，不能被网站登录页或访客认证拦住：

```text
https://实际域名/api/shiyu/payments/notify/wechat
https://实际域名/api/shiyu/payments/notify/alipay
```

配置齐全后再设置 `enabled=true`。仍保持 `mode=integration` 做本机联调。本机身份入口只接受本地回环连接，不接受公网和代理转发。

要求 Node.js 24 或更高版本，支付库安装在 `payments/node_modules`。新机器先用包管理器按 `payments/pnpm-lock.yaml` 安装依赖。

```powershell
node payments/manage.cjs check
node payments/manage.cjs live-check
node payments/manage.cjs start
```

- `check` 仅做本地配置检查，不会调用支付服务。
- `live-check` 在凭证齐全后，对真实平台查询一个随机、不存在的订单，检查签名调用；不会创建付款订单或扣款。查询通过不代表付款和回调已验证。
- `start` 在 `http://127.0.0.1:4348` 启动当前页面与支付服务，不停止现有 4318 预览。

另开终端运行：

```powershell
node payments/manage.cjs session
```

打开输出的本机一次性地址，进入会员页。选择一次性月度或年度套餐，即可创建真实订单。**这些支付会真实扣款，金额取后台已上架套餐，不会暗中改成一分钱。** 扫码／收银台确认付款由测试人员操作。

测试付款后检查：页面显示已支付、订单列表可查询、后端会员账本只入账一次。支付宝浏览器返回页不作为支付成功凭据；微信／支付宝均以验签后的通知或可信查询为准。

## 5. 部署注意

当前仓库的旧私有预览部署脚本尚未升级为支付生产部署，不要直接用它开放收款。支付运行包需要 `payments` 代码、依赖及 Node.js 24；`.local/payments` 中配置、证书和数据库须放持久化目录，不随版本替换。
付款页面可暂留本机，但通知地址必须公开 HTTPS 可达。测试身份不能开放给公众。
公开上线前还需要真实用户身份服务、正式会员协议、让业务后端读取支付会员账本，以及备份／恢复配置。此处没有修改现有演示登录和其他业务后台。

node --test payments/test/payments.test.cjs
